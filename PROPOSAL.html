📊 Источники данных: RSS vs Web Scraping

Вариант 1: RSS ленты (РЕКОМЕНДУЕТСЯ)

Как это работает:
Система подписывается на RSS ленты 50+ крупных новостных источников (TechCrunch, Reuters, Bloomberg, локальные издания). RSS — это стандартизированный XML формат, который новостные сайты предоставляют для автоматической доставки контента.

✅ Преимущества:
• Стабильность: RSS формат не меняется при редизайне сайта (формат — стандартный)
• Надежность: Не требует обслуживания при изменении HTML структуры источников
• Легально: Сайты сами предоставляют RSS для автоматического распространения
• Скорость: Встроенная система уведомлений (RSS сайты сообщают об изменениях)
• Дешево в поддержке: Практически не требует обновлений логики парсинга

⚠️ Ограничения:
• Только источники, которые предоставляют RSS (большинство новостных сайтов это делают)
• Некоторые RSS ленты содержат только заголовки (нужно перейти на сайт для полного текста)
• Конкуренты со слабым медиа-присутствием могут быть не покрыты

💰 Затраты на поддержку:
• Минимальные (обновление списка источников 1-2 раза в месяц)
• Примерно 1-2 часа в месяц труда разработчика

Вариант 2: Web Scraping (опционально, для полноты)

Как это работает:
Система загружает HTML страницы сайтов (блоги конкурентов, LinkedIn, Medium и т.д.), парсит структуру, извлекает новости. Когда сайт меняет дизайн — HTML структура меняется — нужно переписать парсер.

✅ Преимущества:
• Полнота: Захватывает данные даже с сайтов без RSS
• Дополнительные источники: Официальные блоги, социальные сети, форумы
• Детальность: Можно парсить больше информации (комментарии, реакции и т.д.)

❌ Недостатки (техдолг):
• Техническое обслуживание: Каждое изменение HTML структуры = нужно переписать парсер
• Непредсказуемые расходы: Конкуренты обновляют сайты — вы платите на ремонт логики
• Хрупкость: Парсер может сломаться в любой момент
• Проблемы с блокировкой: Некоторые сайты блокируют автоматический доступ
• Требует прокси: Для обхода rate limiting — дополнительные расходы
• Легальные вопросы: Не все сайты позволяют скрейпинг (robots.txt)

💸 Затраты на поддержку (ВЫСОКИЕ):
• Регулярное обслуживание: 4-8 часов в месяц (непредсказуемо)
• Срочные исправления: Когда сайт сломался — нужно экстренно чинить
• Итого: +$300-600/месяц дополнительных расходов разработчика
• Альтернатива: Использовать платный сервис (NewsAPI, MediaStack) — +$40-60/месяц

🤖 Технология: Claude 3.5 Sonnet

Почему Claude 3.5 Sonnet?
• Отличное качество анализа за оптимальную цену
• Доставка алертов в течение 30-60 минут
• Хорошо понимает стратегический контекст рынков
• Генерирует качественные рекомендации
• $81/месяц за 100-150 алертов/день

Как считаются расходы?
Каждый алерт требует обработки ~700 токенов (input + output). При 100-150 алертах/день это ~$80-90/месяц Claude API.

🌐 Инфраструктура: Render.com

Почему Render.com?
• PostgreSQL БД включена в план хостинга (экономия $25/месяц)
• Простая развёртка Node.js приложения
• Автоматическое восстановление при сбое
• Git интеграция (автоматическое обновление при push)
• Встроенные логи, метрики, мониторинг
• 99.9% uptime гарантия
• Total: $12/месяц (вместо $20+ на других платформах)

❓ Часто задаваемые вопросы

В: Как быстро приходят алерты?
О: В течение 30-60 минут после публикации статьи в источнике (система проверяет источники каждый час)
В: Какая точность определения конкурентов?
О: Высокая точность выявления: система определяет упоминания конкурентов и фильтрует шум, обучаясь на вашем списке из 16 компаний
В: Можно ли добавить своих конкурентов?
О: Да, полностью. Обновим список в течение часа
В: Какие расходы после разработки?
О: От $94 до $119 в месяц. Обязательные: Claude API ($81) + Render.com ($12) + Домен ($1) = $94. Опциональные: RSS мониторинг и Uptime мониторинг (можно бесплатно или за $25). Подробно в документе "Стоимость"

О: Подписка для разработки без ограничений на токены Claude, чтобы уложиться в сроки
